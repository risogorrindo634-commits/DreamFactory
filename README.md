# DreamFactory

用代码做视频的管线，以及验证它的评测集。第一条垂直管线是**数据故事短片**：给一份简报和一份数据，产出一支带旁白、字幕和图表的讲解视频，并自动检查它对不对。

为什么做这个、为什么先做评测，见[调研报告](docs/llm-video-game-research.md)。

![一支参考影片的抽帧图](docs/images/data-story-contact.jpg)

## 现状

- 一条管线端到端跑通：脚本、时间轴、渲染、自检、成片。
- 18 项自检，全部在运行，每一项都有缺陷样例。旁白由语音合成念出，再由语音识别逐句核对念的内容和数字。有 DeepSeek 密钥时两者都走 DeepSeek 的语音接口，没有时用 Edge 的神经语音和本机的语音识别。
- 评测集：11 个用例，53 条注入缺陷。[最近一次结果](evals/BASELINE.md)是干净用例误报 0/11，缺陷检出 53/53，两种语音组合下相同。
- 一支片子可以自带场景代码：内置场景做不出的画面（比如折线图），由智能体为这支片子现写，同样要过自检。
- 无人值守：模型只拿简报和数据，独立交付影片。DeepSeek 的 `deepseek-flash` 把全部 11 个用例各做了三遍，33 次全部通过，连旁白语音在内每支约 0.04 美元。Fable 5.2 和 Haiku 5.5 做过最初的 7 个用例，也都能做完；Haiku 5.5 每支约 0.01 美元，Fable 5.2 约 0.7 美元，这两个数不含语音。运行记录在 [evals/agent-runs/](evals/agent-runs/)。

## 运行

需要 Node 20 以上、ffmpeg、一种中文字体。旁白语音和听写核对有两种配法：

- **DeepSeek 的语音接口。** 设置环境变量 `DEEPSEEK_API_KEY`，需要联网和 curl。语音合成和语音识别都按量计费，一支 40 秒的中文片子语音约 0.01 美元。
- **免费的组合。** 装两个 Python 包：

  ```bash
  pip install edge-tts faster-whisper
  ```

  `edge-tts` 调用微软 Edge 的朗读语音，需要联网。`faster-whisper` 在本机做听写核对，第一次运行会下载约 500 MB 的识别模型。

两种都配了时用 DeepSeek。都没有时退回离线的 espeak-ng，再没有就用静音轨并按字数估算时长，听写核对显示为跳过。

```bash
npm install
```

```bash
npx playwright install chromium
```

做一支片子：

```bash
node pipeline/cli.mjs run evals/cases/works-by-category --draft
```

成片在影片目录的 `out/film.mp4`，自检报告在 `out/report.md`，抽帧图在 `out/contact.jpg`。去掉 `--draft` 得到 1080p、30 帧的成片；加 `--no-video` 只做文字层检查，十几秒完成。

跑评测集，约七分钟：

```bash
node evals/run.mjs
```

## 管线怎么工作

一支片子是一个目录，里面有三个文件：

| 文件 | 谁写 | 内容 |
| --- | --- | --- |
| `data.json` | 任务给定 | 事实来源：数字、数据来源、截止日期 |
| `expect.json` | 任务给定 | 要求：片长范围、必须出现和必须念到的数据 |
| `film.json` | 智能体 | 分镜和旁白，数字一律引用 `data.json` |

运行时依次做五件事：

1. **解析引用**：把 `film.json` 里指向数据的地方填上真实数字。
2. **定时间轴**：先合成每句旁白，量出时长，再据此排出每个场景和每句字幕的起止时间。合成过的句子会缓存在 `.cache/tts/`，同一句话不会合成第二次。
3. **读画面**：在无头浏览器里按时间轴逐点走一遍，直接从页面读出每个时刻屏幕上有哪些文字、在哪里、什么颜色。
4. **渲染**：逐帧截图交给 ffmpeg 编码，混入旁白。
5. **自检**：对画面文字、成片和音轨跑检查，写出报告。

画面完全由时间决定：给定任意时刻就能画出那一帧，所以结果可重复，检查读到的就是观众看到的。

写 `film.json` 的规则和字段见 [DIRECTOR.md](DIRECTOR.md)。

## 自检项

| 检查 | 查什么 |
| --- | --- |
| `data-accuracy` | 画面和旁白里的每个数字都能在数据里找到，写成汉字的也算；要求出现的数据确实出现了 |
| `citation` | 用到数据的画面都标了来源 |
| `readability` | 每段文字停留的时间够读完，字号够大 |
| `layout` | 文字不出画面、不溢出容器、不互相重叠 |
| `crowding` | 文字不被线条或图形穿过，不被盖住，不和别的文字贴在一起 |
| `contrast` | 文字与背景的对比度达标 |
| `subtitles` | 字幕与旁白逐句对应，单句不过长 |
| `sync` | 同一个场景里，旁白念到的数字，画面不能晚出现 |
| `typography` | 没有重复的标点、残留的模板符号、空括号 |
| `empty-frames` | 没有超过 1.5 秒的空画面 |
| `marks` | 标了数值的图形，长短高低与数值一致；自带的图表必须标数值；任务规定了图形个数时个数要对 |
| `determinism` | 同一时刻重画，画面一致，没有用随机数、时钟或上一帧的状态 |
| `fonts` | 中文没有显示成方框 |
| `spec` | 片长、分辨率、帧率、编码、音画等长；任务要求写在画面上的文字确实在 |
| `video-stillness` | 没有黑屏，画面和字幕同时不动的时间不超过 6 秒 |
| `audio-levels` | 响度在 -14 LUFS 上下，峰值不过载 |
| `audio-gaps` | 旁白之间没有过长的无声 |
| `asr` | 语音识别逐句听旁白：字幕里的数字必须都听到，措辞不能是另一句话 |

## 评测集

评测集回答两个问题。

**检查会不会冤枉好片子？** `evals/cases/` 下每个用例有一支参考影片，它们不应该触发任何检查。触发了就是误报。

**检查抓不抓得到它声称能抓的问题？** `evals/defects.json` 里每条缺陷只在参考影片上改一处，比如把 483 抄成 583，并写明哪项检查必须失败。没失败就是漏检。

当前用例：

| 用例 | 考什么 |
| --- | --- |
| `works-by-category` | 柱状图、大数字、占比 |
| `cost-per-minute` | 跨四个数量级的区间，对数刻度 |
| `works-by-category-en` | 同一份数据换成英文，管线不改 |
| `monthly-trend` | 要求折线图，内置场景做不出来，必须自己写场景代码 |
| `top-of-long-list` | 24 个乱序品类里选出前 6 名，全放会撑破画面 |
| `twenty-seconds` | 22 秒内讲完三件事，还要留够阅读时间 |
| `derived-numbers` | 简报要倍数和降幅，必须用引用算出来，不能手算 |
| `asks-for-missing-number` | 简报要一个数据里没有、也算不出来的数字，考的是不编数字、不改数据、如实说明 |
| `two-series` | 两条折线画在一张图上并且交叉，图上要写出各自的名字；交叉处两个数只差 7，标签最容易叠在一起 |
| `gap-in-the-data` | 数据中间缺了一个月，不能画成 0，折线要断开并标出原因 |
| `long-report` | 80 到 95 秒的年度盘点：大数字、柱状图、折线图、区间图各一个，十几个必须出现的数字 |

除了前三个，其余用例用的都是虚构的示例数据，数据来源里写明了这一点。后四个是在三个模型都做完前七个之后加的。

换模型、换语音或视频供应商、改管线之后重跑评测，就能知道有没有变坏。

### 无人值守运行

上面两问考的是检查本身。第三问考的是模型加上导演规范，能不能在没有人的情况下独立交付：

```bash
node evals/agent-run.mjs
```

脚本给每个用例建一个干净的工作区，里面只有管线、`DIRECTOR.md` 和任务的简报、数据、要求，没有参考影片。模型只能写任务目录、只能运行管线命令，其余操作会被自动拒绝。模型交付后，脚本用用例原本的数据和要求再复验一遍，并记录管线运行次数、费用和是否守规。

需要已登录的 Claude Code 命令行，会产生模型费用，每个用例默认上限 8 美元。结果写到 `evals/agent-runs/`。

模型每次做出来的片子都不一样，一次通过说明不了稳定。加 `--repeat 3` 让每个用例跑三遍，汇总里会多出每个用例的通过次数，以及有几次是第一次交给管线就通过自检的。

模型可以换成别家的，只要它提供兼容 Anthropic 的接口。DeepSeek 已经接好：

```bash
node evals/agent-run.mjs --provider deepseek
```

- 需要环境变量 `DEEPSEEK_API_KEY`。同一个密钥也用于旁白语音和听写核对。
- 默认用 `deepseek-flash`。导演规范要求看抽帧图，`deepseek-v4-pro` 不能看图。
- 命令行在一个从头搭的环境里运行，你自己的 Claude 登录和设置不会带到别家的接口。
- 命令行按它自家模型的价格计费，给别家模型报出的费用高出约 50 倍。所以这时费用由脚本按供应商公布的单价另算，8 美元的上限不生效，靠每个用例 30 分钟的时间上限兜底。

怎么读这张表：

- **最初的 7 个用例，三个模型都够用。** 折线图用例里，三个模型都为片子写了场景代码并通过全部检查。当时管线还不能引用倍数和降幅，简报却要这两个数；三个模型每次都没有自己算、没有改数据，交付了只含原始数字的版本，并在汇报里写明哪条要求没满足。现在这两个数可以引用了，“如实说明做不到”改由 `asks-for-missing-number` 来考，DeepSeek 三遍都没有编数字，都在汇报里写明了缺什么。
- **DeepSeek 开工前读得多。** 它每个用例先读 19 到 21 个文件，把管线和场景代码看一遍再动笔，所以每个用例 24 到 31 轮，Haiku 5.5 第四遍是 9 到 15 轮。7 个用例里没有一次自检失败，也没有一条命令被拒绝。
- **便宜的模型差在稳定，不在能力。** Haiku 5.5 有两次在第一条探查命令被拒绝后，就认定不能运行任何命令，没有自检就交付。其中一支片子的旁白比画面快几秒，按现在的检查不通过。把放行的权限范围明确写进给模型的说明之后，第四遍没有再出现，但只有 7 次，样本很小。
- **新检查改变了 DeepSeek 的折线图。** 第一遍里，数值标签盖住了纵轴刻度，当时没有检查能发现。加上拥挤检查后的第二遍，模型第一次自检就被拦下（“42 和 100 贴在一起”），自己改了；但它的改法是给标签垫一块和背景同色的底板，底板又盖住了“100”的最后一位，画面上读成“10”。那一版检查没看出来，是人看抽帧时发现的，所以第二遍的这支片子按现在的检查不通过。检查补上逐字核对后的第三遍，交付的折线图刻度和标签都清楚。
- **加难之后 DeepSeek 仍然全过。** 11 个用例各跑三遍，33 次全部通过，其中 31 次是第一次交给管线就通过自检。新加的四个用例没有一次失败。我们看过“两条折线”和“缺一个月”这两个用例交付的六张图：图例没有标反，缺口处折线都断开了，标签没有打架。所以这套用例对它还是不够难，能看出差别的只有返工次数和费用。
- **返工的原因。** 33 次里有 9 次返工过，共 11 处检查失败：听写核对 5 处，画面静止 4 处，数据和图形 1 处，片长 1 处。听写核对的 5 处里有 2 处是真问题：“是 2 到 45 美元”念出来和“12 到 45”一样，“是 1 月的”念出来和“11 月的”一样，模型换了说法。另外 3 处是管线自己的毛病，已经修掉。
- **有一次把路径写错了。** “两条折线”的第二遍里，模型把自己工作目录的路径写错了一个字符，读取被拒绝。指向工作区以外的读取一律记为没有守规，所以这一次的“守规”是“否”；它并没有去读别的地方。
- **条件不完全相同。** Fable 5.2 和 Haiku 5.5 只跑过最初的 7 个用例，没有在新用例上跑过。 Fable 5.2 是在较早版本的脚本下跑的，那时读取范围没有限制，权限说明也不完整。Fable 5.2 和 Haiku 5.5 运行时管线用的还是 espeak 占位语音，听写核对被跳过；DeepSeek 运行时 17 项检查全部生效。两边的费用口径也不同，见“已知局限”。

模型没有正常结束的运行（账号用量限额、费用上限、超时）记为“中断”，不计入结果，可以用 `--only` 单独重跑。

这些运行更大的收获是帮管线找问题。模型的汇报和交付的片子一共暴露了十处：

| 暴露的问题 | 处理 |
| --- | --- |
| 占比显示成 `17%%` | 新增文字规范检查 |
| 片名里的数据引用不生效 | 修正 |
| 成本用例没写货币单位 | 补进数据和简报 |
| 分镜没改的重跑也算一轮 | 运行记录加分镜版本号 |
| 英文单位粘在数字上（`233works`） | 柱状图自动加空格 |
| 区间图的 `scale` 写错时条形画不出来，自检没发现 | 写错直接报错；图形检查增加“宽或高为零” |
| 规范提到退出码，诱导模型在命令后接 `echo` 而被拒绝 | 规范改为“输出开头就是结论” |
| 片尾引用数据截止日期被判成“不在数据里的数字” | 修掉这个误报 |
| 旁白走在画面前面，检查分不出 | 新增同步检查 |
| 模型能读到工作区以外的真实仓库 | 读取限制在工作区内 |

接入 DeepSeek 之后又遇到九处：

| 暴露的问题 | 处理 |
| --- | --- |
| 语音识别把英文数字写成单词（`200 and thirty-three`），听写核对当成没念 | 听写核对能读写成单词的英文数字；新增一条英文念错数字的缺陷 |
| DeepSeek 的声音混音后，真峰值正好压在响度检查的线上 | 混音按实测的真峰值逐轮压低限幅 |
| 命令行给别家模型报的费用高出约 50 倍 | 脚本按供应商公布的单价另算 |
| 折线图的数值标签盖住纵轴刻度，或被折线穿过，检查全部放行 | 新增拥挤检查；参考影片自己也有一个标签被折线穿过，一并修掉 |
| 标签的底板和背景同色，盖住了刻度的最后一位，第一版拥挤检查放行 | 逐字检查每个字母和数字有没有画出来 |
| 短字幕换行时改动的像素太少，画面静止检查时算时不算 | 静止在字幕切换处截断，切换时刻由时间轴给出 |
| 本机识别把“52期”听成“527”，“期”和“七”同音，听写核对误报 | 数字后面紧跟和数字同音的字时，两种听法都算对 |
| 识别结果把数字贴在字母后面（“API2~45”），核对时漏掉这个数 | 识别结果里紧贴字母的数字也算数字 |
| 英文四位数不带千分位，语音按年份念成 twenty-seven ninety-three | 英文旁白的数字带千分位；按年份念的读法也认 |

## 已知局限

- **Edge 语音不是正式的商用接口。** `edge-tts` 用的是 Edge 浏览器朗读功能背后的服务，没有服务协议，适合打样。DeepSeek 的语音接口是有文档、按量计费的正式接口，但它的文档没有写生成音频的使用条款，商用前请自行确认。换供应商只需在 `pipeline/lib/tts.mjs` 里加一个函数。
- **DeepSeek 的语音只有两个声音，不能调语速。** 片长只能靠增删旁白和场景来调。
- **我们没有用耳朵听过这些语音。** DeepSeek 和 Edge 的都没有。语音识别只能证明“听得懂、数字没念错”，证明不了“好不好听”。发布前请人听一遍。
- **espeak 只是占位。** 它的发音连语音识别都听不懂，离线时只用来撑起时间轴。
- **没有背景音乐和音效。**
- **缺陷是和检查一起写的。** 53/53 说明检查能抓到设计时想到的问题，不代表能抓到没想到的问题。无人值守运行里遇到过三个当时没有检查能抓到的问题，两个是模型自己看抽帧图发现的，一个是人看片子发现的。接入 DeepSeek 之后又有两个，都是看抽帧图发现的，其中一个还是在专门为它写的检查通过之后。
- **三条缺陷不是改影片得到的。** `fonts` 和 `audio-levels` 守的是管线的环节，影片内容触发不了，它们的缺陷是直接弄坏那个环节：启动浏览器时拿掉中文字体，把混好的旁白整体调高或调低。拿掉字体只能在 Linux 上做，别的系统上这条缺陷记为“未判定”。
- **检查不懂好不好看。** 构图、节奏、是否有吸引力，仍要靠人或智能体看抽帧图。
- **拥挤检查只看文字。** 它查文字有没有被图形穿过、盖住，或和别的文字贴在一起；图形之间互相遮挡、标签离它的点太远，仍然查不出来。线条只擦到标签一角（不到标签面积的 2%）时放行。
- **汉字数字只认常见写法。** “两千七百”“四点五倍”“九成”会核对；“一半”“翻了一番”“两到三个数量级”这类说法仍然放过。
- **用例仍然偏容易。** 加到 11 个用例、每个跑三遍之后，`deepseek-flash` 仍然 33 次全过。评测拉不开通过率，只看得出返工次数和费用的差别。
- **样本小。** Fable 5.2 每个用例只跑过一两次，Haiku 5.5 跑过四次，其中只有一次是在最终版脚本下，两者都没有做过新加的四个用例。DeepSeek 在最初 7 个用例上跑过两遍，在 11 个用例上各跑过三遍。
- **费用口径不统一。** Fable 5.2 和 Haiku 5.5 的费用是命令行自报的，含它的固定开销，不含语音。DeepSeek 的费用是按公布的美元单价折算的，含旁白语音的原价，不含听写核对。按账户余额核对，33 次运行记了 1.33 美元，余额实际少了 7.26 元人民币，记的数偏高。三者都不含搭管线和写参考影片的投入。
- **派生数字只有三种。** 倍数、升幅、降幅可以用引用算；差值、平均值、几行的合计还不能，规范要求遇到时如实说明，不要自己算。
- **有些要求只能写在简报里，查不了。** 两条线的名字有没有标反、缺口处的折线有没有真的断开、旁白有没有提到数据缺失，检查都看不出来。
- **浏览器重画不是逐位一致的。** 同一时刻重画，偶尔有几十个像素的抗锯齿差异，可重复检查容忍万分之一以内的像素差。
- **只有一种片型，六种内置场景。**
